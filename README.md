## Стек

Vite 8 + SCSS (dart-sass), без фреймворков.

## Структура

```
index.html            # точка входа Vite
src/
  styles/
    main.scss         # собирает партиалы через @use
    _tokens.scss      # цвета, типографика, сетка, тайминги анимаций
    _base.scss        # сброс, базовая типографика, кнопки
    _header.scss      # шапка, бургер, мобильное меню
    _hero.scss        # первый экран
    _problems.scss    # второй блок «Вы здесь, потому что»
    _expertise.scss   # третий блок «Вы эксперт в своём бизнесе»
    _approach.scss    # четвёртый блок «Команда — это актив»
    _frameworks.scss  # пятый блок, карусель
    _gains.scss       # шестой блок, плитка карточек
    _process.scss     # седьмой блок, таймлайн на тёмной подложке
    _team.scss        # восьмой блок, карточки основателей
    _offers.scss      # девятый блок, три тарифа
    _reviews.scss     # десятый блок, отзывы
    _faq.scss         # одиннадцатый блок, аккордеон вопросов
    _cta.scss         # двенадцатый блок, финальный призыв
    _footer.scss      # футер
    _modal.scss       # модальная форма заявки
  js/
    main.js           # импортирует main.scss + логика мобильного меню
    carousel.js       # листание карусели пятого блока
  assets/
    img/hero.webp | hero.png
    icons/*.svg       # < 4 КБ, инлайнятся в сборку как data-URI
    decor/            # градиент панели и декоративные фигуры 3-го блока
```

## Команды

```bash
npm install     # один раз
npm run dev     # дев-сервер с HMR на http://localhost:5173
npm run build   # продакшен-сборка в dist/
npm run preview # локальный просмотр собранного dist/
```

Node ставился через nvm, поэтому в новой сессии терминала он подхватывается
из `~/.zshrc`. Если `node` не найден — `source ~/.zshrc`.

## Реализовано

- Десктоп совпадает с макетом по координатам (1440px).
- Брейкпоинты: 1200px (планшет), 1024px (переключение на бургер), 900px и 640px (мобильные).
- Бургер-меню: морфинг линий в крестик, выезд панели, ступенчатое появление пунктов,
  размытая подложка, блокировка скролла, закрытие по Esc / клику по подложке / клику по ссылке,
  атрибуты `aria-expanded` и `aria-controls`, поддержка `prefers-reduced-motion`.
- Картинка героя: WebP 139 КБ (PNG 1.2 МБ как фолбэк), заданы `width`/`height` против CLS.
- Плашки: на десктопе лежат на разделительной линии, на мобильных — колонкой по центру под линией.
- Второй блок: сетка карточек 3 / 2 / 1 колонки.
- Третий блок: фиолетовая панель заходит на светлую карточку на 72px, градиент из макета
  обрезается панелью.
- Декор в цветной панели: фигуры повёрнуты на 90°, поэтому координаты из Figma API
  (`x`/`y` — точка ДО поворота) не совпадают с видимым боксом — он сдвинут влево на ширину
  фигуры. Итоговые значения: уголок 112px в 56px от правого края, звезда 128px в 24px
  от левого. Точная геометрия держится от 1400px; ниже фигуры уходят в углы,
  иначе заголовок на них наезжает.
- Отступы между блоками: 120px на десктопе, 80px на мобильных. Правило — каждый блок
  задаёт только свой `padding-top`, `padding-bottom` у предыдущего блока равен нулю.
  У блока карусели отступ задан `margin-top`, а не `padding-top` — у него своя подложка,
  и она должна начинаться после отступа. Когда добавится следующий блок,
  нижний отступ у `.frameworks` нужно будет вынести в него.
- Карусель: нативный скролл со scroll-snap, без библиотек — свайп работает из коробки,
  кнопки листают на слайд + gap и блокируются на краях. Лента вынесена
  из контейнера и идёт во всю ширину секции, иначе карточки обрезались бы по невидимой
  границе контейнера, а не по краю экрана. Поля ленты (`padding-inline`) равны левому полю контейнера: первая карточка выровнена
  по заголовку, последняя в конце прокрутки стоит на том же расстоянии от края.
  `scroll-padding-left` — чтобы туда же попадала привязка scroll-snap. Ширина слайда
  считается от контент-бокса ленты, поэтому в формуле вычитается 64px, а не 128px.
  Слайд не растягивается сверх макетных 416px. На мобильных gap равен полю, поэтому
  следующая карточка начинается ровно за краем экрана и ничего не обрезается.
  Перетаскивание мышью — на pointer-событиях, тач не перехватываем (нативная инерция лучше);
  после отпускания лента доводится до ближайшего слайда. Высота слайда фиксирована (520px),
  картинка прижата к верху, текст к низу — у длинных подписей он заходит на прозрачный
  низ иллюстрации, как в макете. Ниже 1024px — обычный поток, чтобы текст не перекрывал.
- Четвёртый блок живёт в своём контейнере — 1088px контента вместо общих 1312px.
  Картинка широкой карточки позиционирована абсолютно (в макете она заходит под текст),
  поэтому ниже 1200px карточке задана пропорция `1088 / 383` — иначе картинка обрезается.

## Что дальше

- Заменить заглушки: телефон `+7 (XXX) XXX-XX-XX`, ИНН/ОГРН, ссылки на политику
  конфиденциальности и согласие на обработку данных.
- Форма заявки открывается по всем кнопкам-призывам: они помечены общим якорем
  `#contact`, JS перехватывает клик. Без JS ссылка просто прокручивает к блоку записи.
- Отправка формы не подключена к бэкенду: после валидации показывается отдельный экран
  «Заявка отправлена» (в макете его нет). Он закрывается сам через 5 секунд, кнопкой
  «Закрыть» или по Esc; при закрытии форма сбрасывается. Место для запроса помечено
  `TODO` в `src/js/modal.js`.
- Плавный скролл по якорям — `scroll-behavior: smooth` на `html`; в блоке
  `prefers-reduced-motion` сбрасывается на мгновенный.
- В меню пять пунктов; ниже 1200px они поджимаются (gap 24px, кегль 18px),
  иначе на 1025px «Отзывы» наезжали на кнопку «Консультация».
- Якоря навигации проставлены и работают: `#about` → «Команда — это актив»,
  `#tools` → карусель фреймворков, `#pricing` → тарифы, `#team` → основатели,
  `#reviews` → отзывы, `#contact` → финальный CTA. У секций с `id` задан
  `scroll-margin-top: 104px`, чтобы заголовок не уезжал под липкую шапку.
